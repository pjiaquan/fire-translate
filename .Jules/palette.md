## 2024-05-24 - Accessibility improvements for dynamically injected UI and Form Controls
**Learning:** Found that `<select>` elements without adjacent visible `<label>` tags need explicit `aria-label`s for screen reader support. Also, dynamically injected icon-only buttons (like `.history-delete-btn`) are completely opaque to screen readers without an `aria-label`. Buttons globally need `type="button"` to avoid unintended form submission behavior. Finally, explicit `:focus-visible` styling is crucial for interactive elements, as custom CSS often overrides native focus rings.
**Action:** When adding new interactive controls or creating dynamic HTML strings in JavaScript, always double-check for `type="button"`, appropriate `aria-label` (especially for icon-only components), and ensure `:focus-visible` remains visible across all themes and custom styles.
## 2024-05-24 - Accessibility improvements for inline grammar suggestion
**Learning:** Making inline, textual `<span...>` elements behave like buttons for clicking is a bad UX pattern unless they have explicitly declared `role="button"` and `tabindex="0"`, coupled with keyboard handlers for Enter and Space keys. Space key needs special treatment with `e.preventDefault()` so it doesn't just scroll the page down while focused.
**Action:** Always check interactive `<span...>` and `<div...>` elements for full accessibility mapping. Implement both HTML attributes and full keyboard accessibility in JavaScript.
## 2024-05-24 - Accessibility improvements for dynamic icon-only buttons
**Learning:** Found that dynamic icon-only buttons (such as a 'Copy' button changing to a checkmark, or a 'TTS' button changing to a stop icon) become an accessibility failure if their `aria-label` and `title` attributes are statically defined. Screen readers will continue to announce the original function (e.g., "Read Aloud") even when the button now visually performs the opposite or alternate function (e.g., "Stop Reading").
**Action:** When swapping out the inner SVG/HTML of an icon-only button to represent a new state or action, always synchronously update its `title` and `aria-label` attributes to match the new visual state and action. Ensure they are restored when the state reverts.
